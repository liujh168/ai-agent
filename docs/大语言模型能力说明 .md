# 大模型能力说明（2026 修订版 · 含能力归属界定）

> 本文件用于描述当前新一代大模型的能力范围、典型用法与能力边界，可作为产品介绍、系统提示词或使用说明的底稿。
> 本次修订的两项核心工作：**① 校正"大语言模型"的术语严谨性；② 为每一项能力标注归属，严格区分模型本体能力、服务端推理代码能力与用户侧智能体代码能力。**

---

## 一、术语界定：还能叫"大语言模型"吗？

**严格来说，一旦能力描述涉及图像、音频、视频，"大语言模型（LLM）"这个词就不再严谨。**

| 术语 | 严格含义 | 是否适用于本文档 |
| --- | --- | --- |
| **大语言模型 LLM** | 以文本 token 序列为输入输出、做下一 token 预测的语言模型 | ❌ 过窄。仅覆盖纯文本能力 |
| **多模态大模型 MLLM / 原生多模态模型** | 文本、图像、音频、视频在同一表示空间内统一编码与生成 | ✅ 覆盖理解与生成侧的多模态能力 |
| **基础模型 Foundation Model** | 可被下游适配的通用预训练模型总称，不限定模态 | ✅ 最稳妥的统称 |
| **智能体系统 Agent System** | 模型 + 推理服务 + 工具 + 编排代码构成的整体 | ✅ 覆盖"交付文件""执行任务"等系统级能力 |
| **AI 助手 / AI 产品** | 面向用户的完整产品形态 | ✅ 用户视角的称谓 |

**本文的处理方式**：

- 正文中统一使用**「大模型」或「基础模型」**作为主体称谓；仅在专指文本能力时保留"语言模型"；
- 凡涉及系统级能力（联网、执行、文件交付），明确主语为**「智能体系统」**而非"模型"；
- 若你的文档必须沿用 LLM 一词，建议开篇加一句限定："本文所称 LLM，泛指以大语言模型为基座、扩展了多模态与工具使用能力的基础模型及其所属智能体系统。"

**另一处常见的措辞越界**：说"模型支持 100 万 token 上下文"。上下文窗口长度由模型架构（位置编码、注意力实现）与推理服务共同决定——模型权重决定了它**能被训练到多长**，而实际可用的窗口、截断策略与 KV Cache 管理属于推理服务侧配置。严谨表述是"该模型在服务配置下支持最长 X token 上下文"。

## 二、能力归属的三层框架

一切能力都可归入以下三层。这是全文的标注基准：

| 层 | 名称 | 是什么 | 是否属于"模型能力" |
| --- | --- | --- | --- |
| **M 层** | **模型本体能力** | 由训练得到的权重参数决定，一次前向计算即可产生。包括：语言理解与生成、跨模态编码器对齐、世界知识、思维链与自我修正、风格与指令遵循、函数调用意图的生成 | ✅ 是 |
| **S 层** | **服务端推理代码** | 模型之外但由服务方运行的代码：分词/解码、采样策略、上下文窗口管理与截断、KV Cache 复用、结构化输出约束、工具调用协议的解析与分发、安全过滤、推理算力档位调度、服务化的记忆写入 | ❌ 否 |
| **A 层** | **用户侧智能体 / 工具代码** | 宿主应用与外围工具：联网检索、代码执行沙箱、文件解析与封装（docx/pptx/xlsx/pdf）、MCP 客户端与 Server、向量库与长期记忆存储、多智能体编排、定时任务、人工确认与审计 | ❌ 否 |

**一句话判据**：

> 把权重文件单独拿出来、不给它任何外部代码——它还能做到的事，才算模型能力。需要额外代码参与才能实现的，一律是系统能力。

据此可得三条关键结论：

1. **模型只输出 token。** 它不产生文件、不发出 HTTP 请求、不执行代码、不画像素之外的图元。凡"交付成品""联网查证""运行验证""跨会话记忆"，都是模型输出意图/内容后由 A 层代码完成的。
2. **很多人归因于模型的"聪明"，其实是 S 层与 A 层的功劳。** 例如"稳定输出合法 JSON"主要靠 S 层的结构化解码约束；"记得你上次说过什么"靠 A 层的记忆存储。
3. **反之，很多被当成工程问题的缺陷，其实是 M 层的固有属性。** 例如幻觉源于概率生成本身，无法靠外围代码根除，只能缓解。

## 三、分能力条目与归属标注

> 标签说明：**[M]** 模型本体 · **[S]** 服务端推理代码 · **[A]** 用户侧智能体/工具代码 · **[M+A]** 协同（模型出内容与决策，代码执行）

### 1. 信息处理与问答

| 能力 | 归属 | 说明 |
| --- | --- | --- |
| 通用知识问答 | **[M]** | 知识存储于权重中，前向计算直接产出 |
| 总结概括 | **[M]** | 纯文本到文本的生成 |
| 知识解释与分层表达 | **[M]** | 依赖模型对受众与深度的把握 |
| 长文档理解（跨章节比对、溯源定位） | **[M+S]** | 长程依赖建模是 M；但"能装下"由 S 层的窗口与 KV Cache 决定，超长输入常需 S/A 层做分块、压缩或检索式召回 |
| 联网检索与来源标注 | **[A]** | **纯外围能力。** 模型仅生成"要搜索什么"的意图与查询词；检索、抓取、引用编号绑定均为 A 层代码完成 |
| 信息交叉校验 | **[M+A]** | 比对与判断是 M，取回多源证据是 A |
| 接收 PDF / Word / PPT / Excel 输入 | **[A→M]** | **易被误判。** 模型无法直接读取 .docx/.pdf 二进制：需 A 层先做解析、OCR、版式还原，转成文本+图片后再送入模型。模型理解的是"转换后的内容" |
| 接收图像 / 音频 / 视频输入 | **[A→M]** | 视觉/听觉编码器属 M；但抽帧、重采样、分片、超长视频压缩等预处理由 A 层完成，"原生多模态"不等于"原样吞入任意长度的原始流" |

### 2. 深度推理与问题求解

| 能力 | 归属 | 说明 |
| --- | --- | --- |
| 多步推导、思维链、自我检查与修正 | **[M]** | 长思维链由权重自回归生成，是真正的模型能力 |
| "条件不足时不下结论"的元认知 | **[M]** | 来自后训练对齐，属模型行为 |
| 规划与任务拆解 | **[M]** | 模型输出计划文本 |
| 推理深度档位（快思考/慢思考，动态分配算力） | **[M+S]** | 更长的思考是 M；**但"该用多少算力"的档位选择与调度是 S 层策略**。模型本身不会主动决定给自己加算力 |
| 保证输出格式合法（JSON/XML/表格） | **[S]** | 主要靠受限解码、语法约束等 S 层机制，而非模型自律 |

### 3. 创意与写作

| 能力 | 归属 | 说明 |
| --- | --- | --- |
| 各类文体生成、润色改写、风格模仿、角色扮演、多版本产出 | **[M]** | 纯模型能力，无外部代码参与 |

### 4. 多模态理解与生成

| 能力 | 归属 | 说明 |
| --- | --- | --- |
| 跨模态语义关联（看图说话、图文混合推理） | **[M]** | 统一表示空间内的对齐由训练得到 |
| 图像生成 / 图像编辑（产出像素） | **[M]** | 由文生图模型权重直接生成像素，属模型能力（注意：它是另一个模型，不是"语言模型"在画图） |
| 音频/语音输出 | **[M+A]** | 声学模型/声码器是 M；封装为音频文件、流式传输是 A |
| 视频生成 | **[M+A]** | 帧生成是 M；抽帧调度、拼接、编码封装是 A |
| 上传图片后"编辑这张图" | **[A→M→A]** | 解码与回传由 A 层完成，模型只做生成 |

> **关于"文生图是否属于 LLM 能力"**：严谨表述应为"由多模态生成模型产出"。把它写成"大语言模型能画图"是归因错误——语言模型部分只负责理解你的描述、可能参与提示词扩写，真正的像素由生成模型输出。

### 5. 智能体与工具调用

| 能力 | 归属 | 说明 |
| --- | --- | --- |
| 生成"我要调用某工具、参数是 X"的意图 | **[M]** | 经工具调用微调后的模型行为 |
| 工具的协议解析、实际执行、结果回灌 | **[S+A]** | Function Calling / MCP 的 schema 校验、传输、执行全在代码侧 |
| 多步自主执行、失败重试、动态调整 | **[M+A]** | 每一步"下一步做什么"由 M 决策；循环控制、状态记录、错误捕获由 A 编排 |
| 文件级交付（Word/PPT/Excel/PDF） | **[M+A]** | **典型混合能力：模型负责内容、结构、版式意图（或生成相应代码），A 层用 python-docx / python-pptx / openpyxl / reportlab 或 OOXML 打包流程完成格式封装与落盘。** 模型不会"吐出" .docx 二进制流 |
| 图表与数据可视化 | **[M+A]** | 模型定图表类型与数据口径，matplotlib / ECharts 等引擎渲染图元 |
| 联网检索、代码沙箱执行、浏览器操作、数据库访问 | **[A]** | 全部由外围工具完成 |
| 多智能体协作（角色分工、消息协议） | **[A]** | 编排层能力，模型只是每个角色内部的"大脑" |
| 人在回路确认、权限白名单、沙箱隔离、审计追溯 | **[A]** | 安全治理属于系统设计，不是模型能力 |

### 6. 编程与数据任务

| 能力 | 归属 | 说明 |
| --- | --- | --- |
| 代码生成、补全、重构、Bug 定位、解释、测试编写 | **[M]** | 纯模型能力 |
| 在沙箱中真实运行代码以验证结果 | **[A]** | 执行环境由外围提供；模型只能"纸上推演"，跑不跑得通靠 A 层反馈 |
| 数据清洗、统计计算、可视化出图 | **[M+A]** | 代码是 M 写的，执行与出图是 A |
| 输出可交付的数据文件与分析报告 | **[M+A]** | 同 5 中"文件级交付" |

### 7. 翻译与跨语言

| 能力 | 归属 | 说明 |
| --- | --- | --- |
| 多语种互译、润色、本地化改写、术语一致性 | **[M]** | 纯模型能力 |

### 8. 个性化与记忆

| 能力 | 归属 | 说明 |
| --- | --- | --- |
| 单次会话内的长程一致性、指代理解 | **[M+S]** | 依赖 M 的长程建模与 S 的窗口管理 |
| 跨会话记忆（记住偏好、项目背景、历史结论） | **[A]** | **关键澄清：模型权重不会因对话而更新。** 所谓"长期记忆"是 A 层把历史写入存储（向量库/知识图谱/KV 存储），下次请求时检索回灌进上下文。记忆分层、重要性评分、遗忘机制均为 A 层设计 |
| "越用越懂业务" | **[A]** | 是系统积累的效果，不是模型被训练了 |

### 9. 其他常被归因于模型的能力

| 能力 | 归属 | 说明 |
| --- | --- | --- |
| 定时提醒、例行任务、主动推送 | **[A]** | 调度系统，与模型无关 |
| 并发、限流、延迟、成本核算、模型路由（简单用小模型） | **[S/A]** | 服务与编排层策略 |
| 内容安全过滤、拒答策略 | **[S]**（部分 **[M]**） | 对齐带来的拒答倾向属 M；关键词/分类器过滤、外挂审核模型属 S |
| 引用标注 [citation:N] | **[A]** | 编号绑定由检索管线完成，模型只按约定的占位符输出 |

## 四、典型场景的归属拆解（示例）

以"帮我查某行业最近的数据，做一份 PPT"为例：

| 步骤 | 归属 |
| --- | --- |
| 理解需求、拆解为"检索→整理→设计版式→产出" | **[M]** |
| 生成检索词、判断结果是否够用 | **[M]** |
| 实际联网搜索与抓取 | **[A]** |
| 提炼观点、组织叙事逻辑、写文案 | **[M]** |
| 决定配色、版式、图表类型 | **[M]** |
| 渲染图表图元 | **[A]** |
| 用 python-pptx 写入 .pptx 并落盘 | **[A]** |
| 把成品交付给用户 | **[A]** |

**因此，严谨的表述是：「智能体系统」端到端交付了这份 PPT；模型贡献了其中的理解、推理、规划与内容生成。**

## 五、能力边界与使用须知（Constraints）

**属于模型固有、外围代码无法根除的局限 [M]**：

1. **幻觉**：概率式生成的本质缺陷。RAG、一致性校验、来源标注等 A/S 层手段只能降低发生率，不能消除[citation:3]。
2. **知识时效**：权重中的知识有截止日期，无法自我更新。
3. **推理非完备**：长链条推理、复杂数学、前沿专业问题仍可能出错。
4. **无真实世界行动能力**：模型不具备物理行动能力，具身任务需外部机器人系统。

**属于系统设计与工程实现的局限 [S/A]**：

5. **工具调用可靠性**：多步任务中的任务漂移、误调用、错误恢复失败，本质是编排质量问题，可通过更好的 Agent 设计、白名单、人工确认缓解[citation:4]。
6. **成本与延迟**：深度推理显著提升单次成本，属资源调度问题[citation:4]。
7. **隐私与部署**：是否私有化、数据是否出域，是部署形态选择，非模型属性。
8. **文件兼容性**：成品的格式规范、版本兼容取决于工具链。

**通用须知**：

9. 关键决策（医疗、法律、金融、投资、安全）以官方与专业意见为准。
10. 请勿提交涉密信息或未授权商业机密。
11. 不替代持证专业人士的判断。

## 六、如何更好地使用

- **给足上下文**：背景、受众、格式、字数、禁区越明确，输出越贴合；
- **要过程也要结论**：复杂问题可要求"先列推理步骤，再给结论"；
- **明确产物形态**：直接指定 Markdown / 表格 / Word / PPT / Excel；
- **要求来源与时效**：事实性内容要求标注出处与获取时间（触发 A 层检索）；
- **迭代收敛**：先大纲后细节，优于一次求全；
- **定向纠错**：指出偏差点即可，不必重来。

## 七、本次修订要点

| 修订项 | 说明 |
| --- | --- |
| **术语严谨化** | 涉及多模态时不再统称"大语言模型"，改用"大模型 / 基础模型 / 多模态大模型"；系统级能力主语改为"智能体系统" |
| **新增三层归属框架** | 明确 M（模型本体）/ S（服务端推理代码）/ A（用户侧智能体代码）的划分与判据 |
| **全文能力条目标注归属** | 每项能力标明 [M]/[S]/[A]/[M+A]，并给出归属理由 |
| **澄清文件交付** | 模型出内容与结构，代码封装格式与落盘；模型不产生 .docx 二进制流 |
| **澄清长期记忆** | 权重不因对话更新；跨会话记忆是 A 层存储与检索回灌 |
| **澄清文件/多模态输入** | 模型不吃二进制文件；PDF/Word 需 A 层解析转换，视频需抽帧预处理 |
| **澄清文生图归属** | 像素由生成模型产出，非"语言模型在画图" |
| **边界按归属重分** | 模型固有局限（幻觉、时效）与工程局限（可靠性、成本、部署）分开陈述 |
