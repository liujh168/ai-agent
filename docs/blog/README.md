# blog/ — 开发博客

本目录存放项目开发过程中的总结、体会、踩坑笔记等一次性文章。

---

## 写作规范

### 文件命名

中文标题（建议 ≤ 30 字符），无需 slug 化。例如：
```
2026-09-21-为什么我们的Skill用Markdown而不是YAML.md
```

### 推荐的 Frontmatter 模板

如果你的博客工具（如 Hugo）需要 frontmatter，建议用以下模板：

```markdown
---
title: "文章标题"
slug: "kebab-case-slug"
date: "2026-09-21"
author: "你的名字"
tags:
  - Skill
  - 设计决策
categories:
  - Agent 工程
excerpt: "一句话摘要，用于列表页展示"
---
```

如果不使用任何静态站点生成器，frontmatter 也是可选的——纯 Markdown 正文即可。

### 内容建议

- **以"问题"驱动**：先写遇到了什么问题，再写怎么解决的，最后写学到了什么
- **代码片段真实**：引用本项目代码时标注文件路径 + 行号（可参考 `../project/设计决策清单.md` 的风格）
- **不做过度承诺**：踩坑文章不需要给出"完美方案"，把"这个方案在 XX 场景下行不通"说清楚就很有价值

## 与其他目录的关系

| 目录 | 区别 |
|------|------|
| `../project/` | 项目**技术文档**——给人看的设计决策、架构说明，随代码同步更新 |
| `../knowledge/` | **外部知识源**——喂给 RAG 的参考资料，不随代码频繁变动 |
| **本目录** | **一次性文章**——写完就归档，不随代码迭代修改 |
